## What's new in 1.3.0

The app is organized into capability modules, following the architecture proposed by @marcjoancr in [#14](https://github.com/sintax-tech/mcp-for-nextcloud/pull/14). New permissions use the existing matrix layout.

- **OAuth host withdrawal ([#28](https://github.com/sintax-tech/mcp-for-nextcloud/issues/28)):** removing a CIMD host revokes its pending consents, codes and tokens. Re-adding it does not restore credentials: sign in again. This does not establish Zapia interoperability. Authorization metadata advertises the `iss` callback parameter (RFC 9207), and consent preserves the original issuer.
- **HTML mail drafts ([#30](https://github.com/sintax-tech/mcp-for-nextcloud/issues/30)):** `mail_create_draft` accepts `html: true`; plain text remains the default. The plan shows sanitized HTML, and confirmation saves a draft without a signature or sending mail.
- **Deck completion and archiving ([#27](https://github.com/sintax-tech/mcp-for-nextcloud/issues/27)):** complete/reopen and archive/unarchive cards through separate confirmed operations, using the existing `deck.edit` grant.
- **Task status ([PR #29](https://github.com/sintax-tech/mcp-for-nextcloud/pull/29)):** create/edit accepts `NEEDS-ACTION`, `IN-PROCESS`, `COMPLETED` and `CANCELLED`, with consistency checks against progress.
- **Reading the current file version:** `files_version_read` reads the listed current version when there is no separate historical file, fixing a defect present in 1.2.5. Other missing versions remain refused.
- **File version order:** `files_versions_list` returns versions newest first and applies `limit` after ordering, fixing a defect present in 1.2.5.
- **Filtered server log reads:** `logs_list` and `logs_analyze` no longer time out with filters: they read in bounded blocks under a 1000 ms budget and continue from `scan.nextOffset` when `scan.timeBudgetReached` is true, fixing a defect present in 1.2.5.
- **Deck assignment ([#26](https://github.com/sintax-tech/mcp-for-nextcloud/issues/26)):** `deck_edit_card`, `deck_create_card` and `deck_create_board` save assignments when push preparation/delivery fails, using a deferred retry after withdrawing the earlier notification. Delivery failures remain warnings; an unconfirmed withdrawal prevents retry to avoid duplicates.
- **Calendar reminders ([#24](https://github.com/sintax-tech/mcp-for-nextcloud/issues/24)):** create/update accepts up to five DISPLAY reminders relative to the event start. Omission preserves alarms on update; `alarms: []` removes only that DISPLAY/start subset. Other alarms and recurrence overrides remain; notification delivery is not verified. `calendar_list_events` returns these reminders in `alarms` and counts others in `otherAlarms`; confidential events and read-only shares expose none.
- **Forms structure ([#1](https://github.com/sintax-tech/mcp-for-nextcloud/issues/1)):** add, reorder or delete questions/options and change a question type with the existing `forms.edit` grant on the checked Forms 5.3.0, 5.3.7, 5.4.0 and 5.4.1 APIs. The Edit forms help now lists these operations; review existing `forms.edit` grants, which include them. Deletion can orphan answers; deleting an upload question can trigger asynchronous folder cleanup. Confirmation is required.
- **Polls writing ([#1](https://github.com/sintax-tech/mcp-for-nextcloud/issues/1)):** configure or change poll state, manage/remove/restore options, manage shares and send an individual invitation, with separate grants and native editing permission. No automatic vote or automatic retry; an invitation receipt does not prove delivery.
- **Tables schema and sharing ([#1](https://github.com/sintax-tech/mcp-for-nextcloud/issues/1)):** create/update tables, columns and views with `tables.schema`; share/revoke user/group access with `tables.share`. Initial supported ranges are Tables 1.0.10 ≤ version < 1.0.11 on NC32, and 2.2.2 ≤ version < 2.2.3 or 2.3.1 ≤ version < 2.3.3 or exactly 2.4.0 on NC33–35, with a matching native API. These ranges are separate from existing row tools; no schema deletion or public link is exposed. Schema and sharing work with Tables 2.4.0 on Nextcloud 33–35, preserving view layouts and card sources.
- **Collectives ([#22](https://github.com/sintax-tech/mcp-for-nextcloud/issues/22)):** list/read/search pages, create empty pages, edit Markdown, and move/rename within a collective. On NC33–35, create collectives and list/manage members with separate `collectives.collective.create`/`collectives.members` grants. No page/collective deletion, ownership transfer, attachments, templates or sharing management. Supported versions and native effects are detailed in the [README](README.md).
- **Full in Tables and Collectives:** Full includes Tables structure/sharing and collective creation/members. Saved grants are unchanged: an earlier Full without these operations appears as Custom until an administrator chooses Full again. Read denies them; None denies all. Polls presets and labels remain unchanged, with independent grants selected separately.
- **Administration:** round radio outlines and a wider OAuth allowed-hosts field improve the existing controls without changing the permission matrix layout.
- **Tables row receipts:** plain numeric values such as `42` and `42.0` no longer produce a false “different value” warning after `tables_create_row` or `tables_update_row`. Changed numbers, text and other values still produce the warning.

**Updating runs a database migration and the CIMD initialization repair step.** Credentials for hosts that remain allowed survive. Credentials from hosts that were never allowed can no longer authenticate or refresh; an administrator must allow the intended host and the client must sign in again. The existing host allowlist is preserved.

## What's new in 1.2.2–1.2.5

See [the changelog](CHANGELOG.md#125--2026-10-31) for the full changes.

- **1.2.5: fix for reading PDF, DOCX and ODT files ([#25](https://github.com/sintax-tech/mcp-for-nextcloud/issues/25)).** Some documents made `files_read` and the other reading tools fail with a "Malformed UTF-8" error. Extracted text now always comes back as valid UTF-8: emoji and other characters from PDFs are kept, DOCX and ODT files in a declared legacy charset are converted, and unreadable bytes become U+FFFD. No database change.
- **1.2.4: fixes ([#20](https://github.com/sintax-tech/mcp-for-nextcloud/issues/20), [#21](https://github.com/sintax-tech/mcp-for-nextcloud/issues/21), [#23](https://github.com/sintax-tech/mcp-for-nextcloud/issues/23)).** The Notes tools find the folder chosen in the Notes app, also with a translated name; image search reports a missing tag or a failed search; the download of a client's metadata before the OAuth consent page has a 5-second limit (name resolution not included); the Administration page loads fewer small scripts. A group grant this version does not recognize now denies only itself, and administrators can clear it in the group editor with a recorded confirmation. File deletion says that Nextcloud tries the trash bin first and may delete permanently if that fails; the receipt says when the item was seen in your own trash bin. New calendar events carry one `DTSTAMP`, a new contact keeps the UID of its plan (confirmation needs the plan's `plan_state`), `talk_attach_file` shows the path inside your files, and "plan changed" warnings say what changed. No database change.
- **1.2.3: fix for the blank Administration page ([#21](https://github.com/sintax-tech/mcp-for-nextcloud/issues/21)).** On some managed hosts the Administration → MCP for Cloud page could stay blank for minutes because one of its scripts received no answer. That script is now part of another one the page already loaded; permissions and access levels are unchanged. No database change.
- **Mail ([#1](https://github.com/sintax-tech/mcp-for-nextcloud/issues/1)):** Search and read messages and attachment text, open native links, and send, draft, flag or move messages with separate opt-in permissions.
- **Tables ([#1](https://github.com/sintax-tech/mcp-for-nextcloud/issues/1)):** Read tables and authorized rows; create or edit one row while respecting native permissions and view filters.
- **Forms ([#1](https://github.com/sintax-tech/mcp-for-nextcloud/issues/1)):** Read forms and permitted responses, create private forms with initial questions/options, and edit one existing question or option. Broader structure changes remain outside 1.2.2.
- **Polls ([#1](https://github.com/sintax-tech/mcp-for-nextcloud/issues/1)):** Read polls, permitted results and existing links, and create private text/date polls. Managing existing options and settings remains future work.
- **Files ([#20](https://github.com/sintax-tech/mcp-for-nextcloud/issues/20)):** Optional deletion of eligible local files and folders, with explicit confirmation. Permanent deletion remains possible; recovery is not guaranteed.
- **OAuth ([#19](https://github.com/sintax-tech/mcp-for-nextcloud/issues/19)):** Additional public-client identification when the request omits its client ID; no dynamic registration or demonstrated Le Chat fix.

Writes require explicit permissions and confirmation. Plans describe shared impact and relevant native effects; preview is not universally free of platform effects. See the details below for limits. Issue [#1](https://github.com/sintax-tech/mcp-for-nextcloud/issues/1) remains partially covered.

## What's new in 1.2.1

- **Backup settings ([#17](https://github.com/sintax-tech/mcp-for-nextcloud/issues/17)):** in *Data protection*, choose one folder name directly in each acting user's personal root (default `MCP backups`; `.mcp-backups` is allowed). The folder appears with the first copy. Changing the name never moves or deletes content; all previously configured names, including the legacy default, remain protected against MCP writes and keep the backup-mirror visibility rules.

- **Mail ([#1](https://github.com/sintax-tech/mcp-for-nextcloud/issues/1)):** `mail_list_accounts` and `mail_list_mailboxes` list only the caller's accounts and cached folders/counters. Mail is optional and requires the `mail.read` grant. These calls do not synchronize IMAP, read messages or change mail state. Open the account in Mail once if its folder cache is empty; an old cache can return old information. The opt-in integration cell uses disposable Dovecot and Mail, not a production mail server.
- **Subtasks ([#18](https://github.com/sintax-tech/mcp-for-nextcloud/pull/18)):** tasks return their `parent`; create and edit set it within the same calendar or clear it with `null`, and `tasks_list_tasks` lists the direct subtasks of one parent. Loops and nesting deeper than 64 levels are refused; confirmed MCP parent writes run one at a time and need the server's file locking. Contributed by @mturgeonferland.
- **Visibility:** a nested ordinary folder named `MCP backups` is no longer mistaken for the user's root backup folder. Scope, exclusion tags and fail-closed checks still apply.

### Deck in 1.2.0

Labels, due time, native dependencies and a native file link are part of this release. The app does not imitate an API that is absent, and it does not upload, copy or delete the file.

- **Labels** (`deck_list_labels`, `deck_edit_card_labels`) are available on Nextcloud 32 through 35 when Deck is enabled. Proved Deck releases: 1.16.8, 1.17.7, 1.18.5 and 1.19.0. A label from another board is refused. The write changes only the requested ids.
- **Due time** is read and written with the card. Input is a local date `YYYY-MM-DD` (midnight in the account time zone), `YYYY-MM-DDTHH:MM` or `YYYY-MM-DDTHH:MM:SS` in that time zone, or a time with `Z` or `±HH:MM`. The card returns `duedate` as the local date and `dueAt` as an ISO time with the account offset. There is no IANA field. `overdue` stays day-based. A local time that does not exist (a daylight-saving gap) is refused. `dueBefore` stays date-only.
- **Dependencies** (`deck_read_card_dependencies`, `deck_add_card_dependency`, `deck_remove_card_dependency`) appear only on Nextcloud 34 and 35, proved with Deck 1.18.5 and 1.19.0. On Nextcloud 32 and 33 those tools are absent. Direction is outgoing: `cardId` is the origin and `targetId` is the card it depends on. `assignDependentCard(A, B)` stores B in the dependent cards of A. Self-relations and cycles through readable cards are refused. A relation to a card you cannot read is omitted, with no count and no id. A cycle through those cards cannot be detected. A concurrent change between the last check and the native write can still create a cycle.
- **Files** use the native Deck share (share type 12) on Nextcloud 32 through 35. `deck_list_card_files` and `deck_unlink_card_file` are on all four versions. `attachmentId` is the share id and is not the `fileId`. Listing needs `deck.read` and `files.read`. Unlinking needs `deck.edit` and `files.read`, keeps the original file, and an editor of the card can remove a visible association created by someone else. Independent shares may keep access. A missing association and one you cannot see share one refusal: no count and no handle. Opening the card in Deck is the generic next step, and that answer does not confirm that a hidden association exists. This app does not unlink a hidden file. A folder you can already see, and an archived card or board you can already see, are refused in plain language.
- **Linking** (`deck_link_card_file`) needs three grants that already exist: `deck.edit`, `files.read` and `files.share`. Reading and unlinking do not need `files.share`. The plan shows the file path, the owner, whether this is a reshare, the current recipient total, a limited list of names, the shares you created, and read-only access (READ=1) for current members and for people who later join the board, a group or a team (a Nextcloud circle). Unlinking that share removes it for everyone. Access is checked only when the link is created. The server does not revoke the link afterwards. A policy turned on later, a change of board, group or team membership, and the moment between the last check and the native share can change who can read the file. The plan hash does not make the share atomic. The server does not attest human consent. A new plan or an uncertain result is not a record that the write succeeded or that a person approved it.
- **Refusals** use the same answer when the facts cannot be read. A link is refused for a Guest (the hide-users override is not applied to this OAuth session), for group-only sharing, when group sharing is off and the board includes a group or a team, when internal expiry is mandatory, when sharing or resharing is off, and when a recipient is not a fully resolved local user, group or team. Those answers do not ask you to change a setting or to sign in another way.

## What's new in 1.1

- **1.1.2: security fix for guests of the Guests app.** The restrictions of Guests (apps allowed to guests, hidden external storage, sharing only within the guest's groups) now apply on every MCP request, with an app password or OAuth, and on checkout links; the tools of apps a guest may not use are left out. Nothing changes for accounts that are not guests. No database change.
- **1.1.1: fix for the group, resource and permission matrix screens ([#11](https://github.com/sintax-tech/mcp-for-nextcloud/issues/11)).** When the server's answer to a save cannot be read (for example a proxy or an expired session returning a page instead of data), *Group grants*, *Resource scope* and the permission matrix now say the result could not be confirmed and show what is saved, instead of "Saved" or a stale screen. No database change.
- **1.1.0: group permissions, per-resource scope and hardened tag exclusion.**
  - **Permissions by native Nextcloud group:** administrators can grant *Can connect* and module operations to native Nextcloud groups (single `'Database'` backend) in *Access and permissions → Group grants*, with a preview before saving (permissions added and removed, current members, credential holders that may be signed out). Groups only grant; they never deny or narrow, and individual user overrides (`Allow` or `Deny`) take precedence over group grants. Non-native groups (LDAP, SAML, third-party apps or multi-backend groups) are shown as disabled with the reason; grant access to their members individually. See [Group permissions, guarantees and limits](README.md#group-permissions-guarantees-and-limits). Individual overrides can be returned to group inheritance from the permissions table, with a before-and-after preview and undo, and an **Access inspector** explains the effective access of a user; see [Individual overrides, reset and the access inspector](README.md#individual-overrides-reset-and-the-access-inspector).
  - **Per-resource scope (Files, Calendar and Tasks):** administrators can restrict a user from "All resources the user has in Nextcloud" to an explicit allow-list of folders, event calendars (`VEVENT`) or task lists (`VTODO`), kept independently of each other even when one Nextcloud calendar holds both events and tasks, up to 200 items per user and module, without revoking existing OAuth connections. It only narrows access, is set per user by administrators only and never by group. A folder, calendar or task list outside the scope answers "not found", and a scope that cannot be read answers 503. Precedence is always `Per-resource scope > Exclusion by system tag > Native Nextcloud ACL`. After the access and operation permission checks, an unreadable resource scope returns 503 before any item is looked up. Notes is outside the Files folder scope. See [Per-resource scope](README.md#per-resource-scope).
  - **Excluded from MCP access — folder protection and reference filtering:** while any exclusion tag is configured, MCP refuses to share, create/update a public link, copy, or move to another directory any **folder** (and hides `url` on existing folder public links in `files_list_shares`), while individual files and same-parent folder renames keep working. Structured file references are checked against tag exclusion: Talk attachments (`talk_read_messages` withholds `attachmentId`; `talk_attach_file` and `talk_quote_file` refuse an excluded file) and Tasks `ATTACH` links (on any host, IP, loopback or alias) are omitted from the response when their file is excluded **or outside the user's per-resource folder scope**, and the stored data is not changed. Root resolution above mount points fixes false "not found" results on external storage and individually shared team-folder files when exclusion tags are active ([#4](https://github.com/sintax-tech/mcp-for-nextcloud/issues/4)).
  - **A redesigned *Access and permissions* tab:** the matrix shows one level per module (*None*, *Read*, *Edit*, *Full*) chosen from a small window on the cell, with an *Operations* view for each operation; only real exceptions are marked, each row has one actions menu, and a selection bar changes several people at once. The groups appear in a list beside the open group, with its own scroll and a filter (*All*, *With grants*, *Blocked groups*) that stays usable with hundreds of groups, and the resource scope and the access inspector open in side drawers. The page works on a phone and the keyboard focus is always visible ([#2](https://github.com/sintax-tech/mcp-for-nextcloud/issues/2), [#3](https://github.com/sintax-tech/mcp-for-nextcloud/issues/3)).
  - **OAuth clients registered by the administrator:** self-hosted MCP programs that take a manually configured `client_id` and return to their own domain can sign in, with exact redirect addresses, port included; turning one off or deleting it ends its sessions at once. By @Zegorax ([#8](https://github.com/sintax-tech/mcp-for-nextcloud/pull/8), [#7](https://github.com/sintax-tech/mcp-for-nextcloud/issues/7)). See [Self-hosted harnesses](README.md#self-hosted-harnesses-custom-redirect-uri).
  - **German:** the whole interface and the messages of the tools, by @matt-ek ([#10](https://github.com/sintax-tech/mcp-for-nextcloud/issues/10)).

Upgrading from 1.0.8 runs the native schema migrations automatically (tables `mcp_group_grants`, `mcp_policy_state`, `mcp_auth_users`, `mcp_policy_events`, `mcp_auth_recheck`, `mcp_group_life`, `mcp_scope_modes`, `mcp_scope_items` and `mcp_oauth_clients`, which also receives the native client's switch, plus generation columns on OAuth tables): no manual step, no `occ`, and every existing user grant and connection continues as before. **Important:** once you adopt group grants or per-resource scopes, do not downgrade the app to 1.0.8; see [Upgrading, incidents and rollback](README.md#upgrading-incidents-and-rollback).

From 1.0.0 on the app is published in the [Nextcloud App Store](https://apps.nextcloud.com/apps/mcp), signed with the store certificate. The full list, including the security fixes, is in [`CHANGELOG.md`](CHANGELOG.md).

- **1.0.0 and 1.0.1: the App Store.** First signed release in the store (no functional change since 0.11.1); 1.0.1 adds the `ai` category.
- **1.0.2: server log.** A read-only module for IT staff, `logs_list` and `logs_analyze`, over `nextcloud.log` through the core's own reader. Only administrators and the groups they choose see the tools, the grant starts off, IPs are masked, the output is marked as untrusted and every read is audited. See [Features](README.md#features). It also fixes `files_image_search`, which failed on Nextcloud 33.
- **1.0.3: Nextcloud 32–35.** The app declares support for Nextcloud 32 to 35, checked by API contract tests against Deck 1.16–1.19 and Talk 22–25. Fixes: editing a Deck card on 1.18/1.19 no longer clears its start date or colour, and Talk respects the lobby when reading and writing.
- **1.0.4: store description.** The description in the App Store (English, Portuguese and Spanish) now lists the server log module added in 1.0.2. No functional change.
- **1.0.5: locked files and licensing.** A note or file open in Text or Nextcloud Office, locked by another person or by a WebDAV client is no longer a generic error: the plan warns about it, and the write is refused before any change with the app or person holding the lock, since when, until when and what to do. Your own manual lock still lets you write, the app never unlocks or takes over a lock, a version restore no longer writes under an open editor, and the checkout upload answers 423. The app refuses the locks Nextcloud reports when it checks; locks of people and apps are also enforced by Nextcloud at the write (with one exception for Text on delete and rename), while a WebDAV token lock is refused only by the app's own check, which is not atomic with the write and may miss a lock taken during the same request (see the known limitations in [`CHANGELOG.md`](CHANGELOG.md)). The repository now follows REUSE, with `NOTICE`, third-party notices and the "Developed by Sintax" credit on the admin page.
- **1.0.6: hidden tags, audited.**
  - **Fix:** with a hidden system tag configured, ordinary files and folders are visible again; since 0.8.0 they were all reported as not found. Backups of hidden files stay hidden. Thanks to @NightDragon1 (#5).
  - **Security:** the tag-based hiding was audited on every access path and the gaps were closed: batch undo, Talk quotes, Notes categories, MCP resources, files reached through local shares, settings that cannot be read, cached decisions and folders named "0". In doubt, the app now refuses. Thanks to @matt-ek (#4) for the report behind the audit.
  - **Server log:** a new admin option, on by default, hides the text of log messages while files are hidden by tags; it can be turned off when your IT team needs the full details. The app's own error log now keeps only the error type and code.
  - **Docs and CI:** the technical README is now available in English ([`mcp/README.md`](mcp/README.md)) and Portuguese ([`mcp/README.pt-BR.md`](mcp/README.pt-BR.md)), and GitHub Actions runs the test suite on PHP 8.2, 8.3, 8.4 and 8.5 and checks the package on every push and pull request.
- **1.0.7: task categories and a clearer admin page.**
  - **Tasks:** the Tasks tools read, write and filter task categories (the VTODO `CATEGORIES` property): `categories` on `tasks_read_task` and `tasks_list_tasks`, `categories` on create and edit (omit to keep them, `[]` clears them, a list replaces them) and a `category` filter on the list. The confirmation plan shows each name before and after a change ([#6](https://github.com/sintax-tech/mcp-for-nextcloud/issues/6)).
  - **Admin page:** five tabs with their own address, searchable pickers for the server log groups and the exclusion tags, and a permission matrix that can show one app at a time and keeps the names in view. Each cell says Allowed, Denied or Unavailable (with the reason), and "Undo" brings the values back for 10 seconds ([#2](https://github.com/sintax-tech/mcp-for-nextcloud/issues/2)). In 1.1.0 the matrix shows one level per module instead of a box per operation (see above).
  - **Excluded from MCP access:** the tag section says what it does and what it does not: it hides files from this connector only, who can assign each tag type, and that the server log tools respect it only while "Hide the text of log messages" is on ([#4](https://github.com/sintax-tech/mcp-for-nextcloud/issues/4)).
- **1.0.8: new name.** The app is now called **MCP for Cloud**: the Nextcloud App Store rules do not allow the Nextcloud name in the name of an app. Nothing changes for you: the app ID, the settings, the permissions and the connections are the same, and there is nothing to do.

Upgrading from 0.7.0 or later runs the schema migrations by itself (tables `mcp_file_batches`, `mcp_oauth_spent` and `mcp_logs_groups`): no manual step, no `occ`, and nothing changes in `config.php`.
