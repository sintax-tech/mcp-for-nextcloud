# Files

| Módulo | Lectura | Escritura |
| --- | --- | --- |
| **Files** | listar y buscar (por nombre o contenido, con fragmentos mediante fulltextsearch), buscar imágenes por etiqueta/fecha, ver imágenes y vistas previas en lote (JPEG, PNG, WebP, GIF, TIFF, PDF), leer texto (TXT/MD, PDF, DOCX, ODT; un escaneo sin texto devuelve `text_layer: false` y, con la aplicación opcional Workflow OCR activa, recibe texto en segundo plano), listar y leer versiones de archivos | editar texto mediante diff y reemplazo parcial, con una copia de seguridad verificada en `/MCP backups` antes de cada escritura (se aplica el versionado de Nextcloud como en cualquier edición); restaurar una versión guardada; prestar cualquier archivo (DOCX, XLSX, PDF, imágenes, hasta el límite de carga) a un agente con shell mediante un enlace de un solo uso; reorganizar carpetas: explorar el árbol, crear carpetas, copiar, mover, mover en lote y deshacer. **Nunca elimina el archivo.** También permite enumerar los recursos compartidos creados por el usuario, compartir un archivo o carpeta propios con una persona, grupo o enlace público (con contraseña generada si se solicita) y eliminar un recurso compartido, lo que retira el acceso, no el archivo. |

| Herramienta | Permiso | Notas |
| --- | --- | --- |
| `files_list` `{path="/"}` | files.read | Elementos hijos directos de la carpeta, con `{name, path, isDir, size, mtime, contentType}`. |
| `files_search` `{query, limit=25, mode="auto"}` | files.read | Busca contenido si `fulltextsearch` y `files_fulltextsearch` están activos y hay índice (incluye fragmentos resaltados); en caso contrario o si hay un error, busca por nombre (interpreta `%`, `_` y `\` de forma literal) y devuelve de 1 a 100 resultados. El parámetro `mode` (`auto` o `name`) fuerza la búsqueda por nombre. |
| `files_read` `{path}` | files.read | Texto sin formato, PDF, DOCX y ODT. Rechaza antes de leer los archivos de más de 20 MiB y trunca el texto a 100 000 caracteres. Un PDF o imagen sin capa de texto devuelve `text_layer: false` y un aviso (no un error); si está activa la aplicación opcional **Workflow OCR** (`workflow_ocr`, requiere `ocrmypdf` en el servidor), procesa el PDF en segundo plano y la siguiente lectura ya devuelve el texto. La página de administración muestra el estado de Workflow OCR. |
| `files_tree` `{path="/", depth=5, limit=2000}` | files.read | Árbol de carpetas con el propietario de cada elemento, para planificar la reorganización sin hacer una llamada por carpeta. Respeta la profundidad (hasta 5) y el recuento (hasta 2000) y avisa si se trunca el resultado. |
| `files_image_view` `{path, max_size=1568}` | files.read | Vista previa reducida en base64 (JPEG/PNG/WebP/GIF/TIFF/PDF) dentro de un límite de bytes (1 MB de forma predeterminada), con alternativa al original para formatos seguros. Incluye metadatos breves. |
| `files_images_view` `{paths?, folder?, limit=6, max_size=1568}` | files.read | Vista previa de varias imágenes (hasta 6) dentro de un presupuesto total de bytes (4 MB de forma predeterminada); el resumen indica los elementos descartados. |
| `files_image_search` `{query?, folder?, modified_after?, modified_before?, tag?, limit=25}` | files.read | Busca exclusivamente archivos de imagen (`image/%`), con filtros por nombre, carpeta, fechas ISO y etiquetas del sistema (incluye las etiquetas automáticas de Recognize). |
| `files_edit` `{path, content, etag?}` | files.edit | Solo archivos de texto existentes, de hasta 10 MiB. Antes de escribir, requiere que `files_versions` esté activa y copia el original a `/MCP backups/<path>/<name>.<YYYYmmdd-HHMMSS>.bak`; si falla cualquier paso, no se escribe nada. Si el `etag` no coincide, tampoco se escribe nada. No crea, mueve ni elimina archivos. Fuera de la carpeta personal, requiere `confirm_shared: true` después de consultar al usuario. |
| `files_replace` `{path, old, new, etag?}` | files.edit | Reemplaza un fragmento que debe aparecer exactamente una vez y devuelve el diff. Requiere lo mismo que `files_edit`: versionado activo y copia en `/MCP backups`; si el `etag` no coincide, no se escribe nada. Fuera de la carpeta personal, requiere `confirm_shared: true`. |
| `files_checkout` `{path}` | files.edit | Acepta cualquier tipo de archivo (DOCX, XLSX, PDF, imágenes) hasta el límite de carga; `files_edit`/`files_replace` solo admiten texto. Devuelve dos enlaces de un solo uso para editar con una herramienta local (curl), sin pasar el contenido por el modelo: la descarga dura 5 minutos y la carga, 15. Cada enlace es una credencial vinculada al usuario, al archivo y al ETag actual; si el archivo cambia antes de la carga, no se escribe nada. La carga crea la misma copia de seguridad que `files_edit`. Fuera de la carpeta personal, solo emite los enlaces con `confirm_shared: true`. |
| `files_upload` `{path, size?}` | files.create | Crea un archivo **nuevo** de cualquier tipo (DOCX, XLSX, PDF, imagen) generado localmente por el cliente, sin pasar el contenido por el modelo. El plan muestra el nombre, la carpeta, la validez del enlace y el límite de carga (igual que `files_checkout`); si `size` supera el límite, se rechaza antes de emitir el enlace. La confirmación devuelve `uploadUrl`, un enlace de un solo uso válido durante 15 minutos y vinculado al usuario y la ruta, junto con el comando `curl -sS -T /path/to/local/file -X PUT -H "Content-Type: application/octet-stream" "<uploadUrl>"`; la respuesta PUT (201) contiene `path`, `size`, `etag` y `fileId`. Nunca sobrescribe un archivo con contenido: si el nombre ya existe, se rechaza durante el plan, la confirmación y la carga. Si otro cliente crea un archivo con contenido con ese nombre entre tanto, o modifica el archivo entre su creación y la escritura, la respuesta es 409 y no se escribe nada (si se crea un archivo vacío al mismo tiempo, la operación se hace cargo de él). Un cuerpo vacío crea un archivo vacío, salvo que el plan declarase `size` > 0 (400). Se rechaza un enlace ausente, usado o vencido antes de escribir el cuerpo en disco. Un cuerpo multipart (400), el exceso del límite (413), un nombre ya existente (409), una carpeta eliminada (404), una carpeta que ahora se comparte (409) o la falta de permiso (403) no consumen el enlace. La carpeta debe existir (`files_mkdir`); una carpeta oculta se trata como inexistente. Fuera de la carpeta personal, requiere `confirm_shared: true`. No hay copia de seguridad porque no existe un original. |
| `files_create` `{path, content}` | files.create | Crea un archivo de texto **nuevo** con contenido incluido (`.md`, `.txt`, `.csv`, `.json`, `.html`, `.xml`, `.yaml`, `.yml`), de hasta 1 MB en UTF-8. El plan muestra nombre, carpeta, tamaño y el comienzo del texto entre comillas. Se aplican las mismas reglas de `files_upload`: nunca sobrescribe archivos con contenido; los nombres que Nextcloud rechace (`IFilenameValidator`) producen un error de argumento sin mostrar el valor; la carpeta debe existir y se requiere `confirm_shared` fuera de la carpeta personal. Para otro tipo o un archivo mayor, usa `files_upload`; para reemplazar un archivo existente, usa `files_checkout`. |
| `files_mkdir` `{path}` | files.create | Crea una carpeta, incluidos los niveles intermedios. Rechaza un destino que ya exista y nunca elimina contenido. Fuera de la carpeta personal, requiere `confirm_shared: true`. |
| `files_copy` `{from, to, etag?}` | files.create | Copia un archivo o carpeta a otra ruta y crea un nodo con ID nuevo; nunca sobrescribe el destino. La copia no conserva ID, versiones ni recursos compartidos. Límite de 2000 elementos y 1 GiB, medido antes de copiar. Fuera de la carpeta personal, tanto el origen como el destino requieren `confirm_shared: true`. |
| `files_move` `{from, to, etag?}` | files.move | Mueve o cambia el nombre dentro del mismo almacenamiento, sin sobrescribir el destino. Devuelve el ID anterior y el nuevo, y el número de versiones y recursos compartidos si las aplicaciones están activas. Entre almacenamientos, Nextcloud lo trata como una copia y cambia el ID. Fuera de la carpeta personal, el origen o el destino requieren `confirm_shared: true`. |
| `files_move_batch` `{moves, mkdirs?, confirm?}` | files.move | Hasta 200 movimientos; primero se crean las carpetas, en el orden dado. Sin `confirm: true`, no escribe y devuelve un plan: qué se podría mover, los conflictos, los rechazos de Nextcloud y los elementos de otras personas. Con `confirm: true`, ejecuta el lote y devuelve `batch_id` para `files_undo_batch`. Si falla un elemento a mitad del proceso, se detiene el lote y lo ya movido queda registrado para deshacerlo. Los elementos de otras personas requieren `confirm_shared: true`. |
| `files_undo_batch` `{batch_id, confirm: true}` | files.move | Revierte un `files_move_batch` en orden inverso. Antes de modificar nada comprueba el lote completo: si algún elemento ya no es el que movió el lote al destino, si la ruta de origen está ocupada o si cambiaron los permisos, no deshace nada e indica qué elemento lo impidió. Solo elimina carpetas vacías creadas por el propio lote; conserva las carpetas con contenido y las devuelve en `kept_dirs`. Es el único lugar donde Files elimina elementos. |
| `files_versions_list` `{path, limit=50}` | files.read | Versiones de un archivo mediante la aplicación `files_versions`, de la más reciente a la más antigua. |
| `files_version_read` `{path, version}` | files.read | Texto de una versión anterior, con los mismos límites y la misma extracción de texto que `files_read`. |
| `files_version_restore` `{path, version, confirm: true}` | files.restore | Restaura el contenido de una versión guardada después de guardar una copia del contenido actual en `/MCP backups`; se aplica la política de versiones de Nextcloud. Requiere `confirm: true` y, como en la edición, rechaza la propia carpeta de copias de seguridad. Fuera de la carpeta personal, también requiere `confirm_shared: true`. |
| `files_list_shares` `{path?, offset=0}` | files.read | Recursos compartidos que ha creado el propio usuario. Con `path`, enumera los del archivo o carpeta propios (se rechaza un nodo de otra persona; los nodos ocultos se consideran inexistentes). Sin `path`, los enumera todos, 50 por página, con `offset` hasta 1000. Cada elemento incluye `shareId`, `type` (`user`, `group`, `link` o `room`), `with` (ID y nombre visible), `permission` (`view`, `edit` o `custom`), `reshare`, `expires`, `hasPassword`, `url` (solo para enlaces), `removable` y `path`. La contraseña nunca se devuelve. Un archivo adjunto de Talk (`room`) aparece con `removable: false` y se elimina desde Talk. Crear y quitar recursos compartidos requiere los permisos `files.share` (personas y grupos) y `files.link` (enlace público), denegados de forma predeterminada. |
| `files_share` `{path, with, permission="view", expires?, note?, password?, confirm: true, plan_state}` | files.share (persona/grupo) o files.link (enlace) | Comparte un archivo o carpeta propia con una persona (`user:<uid>`) o grupo (`group:<gid>`); busca el ID con `users_search` (`include_groups: true` para grupos). Si se vuelve a compartir con el mismo destinatario, se modifica el recurso existente y el plan muestra antes → después, incluido el permiso de volver a compartir que se pierde con un recurso creado desde la web. Si no hay cambios, el plan dice «nothing to change» y la confirmación no escribe nada. `view` = ver y descargar; `edit` = editar (en una carpeta, también añadir y eliminar); nunca concede permiso para volver a compartir. `expires` (YYYY-MM-DD, en la zona horaria de la cuenta, desde mañana en adelante) respeta el máximo del administrador; si se omite, un recurso nuevo recibe la expiración predeterminada del administrador. Antes de escribir, se explican sus reglas (uso compartido desactivado, solo miembros de grupos autorizados o grupos desactivados); los rechazos del núcleo se convierten en mensajes traducidos y el registro conserva solo la clase. Nextcloud avisa al destinatario. Enlaces públicos (`with: "link"`, permiso `files.link`): uno por archivo, solo `view`, y el plan avisa que cualquiera con el enlace puede abrirlo. Se rechazan si el administrador desactivó los enlaces y se respetan la expiración máxima y su valor predeterminado. La contraseña la genera el servidor (evento `GenerateSecurePasswordEvent` de `password_policy`; si no está disponible, 16 caracteres de `ISecureRandom` con letras, números y símbolos), se valida con la política antes de escribir y se crea cuando se solicita `password: true` o el administrador exige una contraseña. Nunca aparece en el plan, los registros ni `files_list_shares`: solo se incluye una vez en el resultado de la ejecución que la generó. Sin `password: true`, se conserva la contraseña actual y no se muestra. El plan incluye `plan_state` (huella opaca de la acción, el recurso compartido y los campos antes/después, sin contraseña), que devuelve la confirmación: si el recurso cambió después del plan, no se escribe nada y se devuelve el plan nuevo con un aviso para volver a comprobarlo; una confirmación sin `plan_state` produce un error de argumento. |
| `files_unshare` `{shareId}` o `{path, with}` + `confirm: true` y `plan_state` | files.share (persona/grupo) o files.link (enlace), según el tipo que se retire | Elimina un recurso compartido creado por el propio usuario en uno de sus archivos o carpetas; nunca toca el archivo. Se identifica mediante el `shareId` de `files_list_shares` (por ejemplo `ocinternal:123`) o con `path` y `with` (`user:<uid>`, `group:<gid>` o `link`). El plan indica quién perderá el acceso («Alex ya no tendrá acceso a X», «todos los miembros del grupo G perderán el acceso», «el enlace de X dejará de funcionar»). Si el recurso es de otra persona, pertenece a un archivo de otro propietario, apunta a un nodo oculto, tiene un tipo no gestionado o usa un ID inexistente, la respuesta es «no encontrado» y no revela información; solo para el adjunto de Talk propio del usuario se indica que debe eliminarse desde Talk. El permiso correspondiente se comprueba después de verificar el propietario, y todo se vuelve a comprobar al confirmar. Igual que con `files_share`, la confirmación devuelve el `plan_state` del plan; si el recurso cambió o se volvió a crear desde que se generó el plan, no se elimina y se devuelve el plan actualizado. |

## Imágenes (`files_image_view`, `files_images_view`, `files_image_search`)

Son herramientas de solo lectura (`files.read`), que respetan la carpeta del usuario y los permisos nativos de Nextcloud:

- **`files_image_view`**: genera una vista previa reducida mediante `OCP\IPreview`, con una dimensión máxima configurable (`max_size`, 1568 px de forma predeterminada). Si la vista supera el límite de bytes (configurable en `image_single_max_bytes`, 1 MB de forma predeterminada), reduce progresivamente la resolución hasta ajustarse. Si no existe una vista previa para ese formato, usa el archivo original para formatos comunes (JPEG, PNG, WebP, GIF), siempre que quepa en el límite. Devuelve un bloque `image` (base64) y un bloque `text` con metadatos (`path`, `mime`, dimensiones originales si se conocen, `size`, `mtime`, `access`, `captured_at`).
- **`files_images_view`**: recibe una lista de `paths` (hasta 6) o una `folder` (con `limit`, 6 de forma predeterminada) y devuelve varios bloques de imagen con un presupuesto compartido (`image_batch_max_bytes`, 4 MB de forma predeterminada). El resumen `skipped` enumera los archivos que exceden el presupuesto o no se pudieron procesar.
- **`files_image_search`**: busca archivos con tipo MIME `image/%`, con filtros opcionales por texto (`query`), carpeta (`folder`), intervalo de modificación ISO 8601 (`modified_after`/`modified_before`) y etiqueta del sistema (`tag`, incluidas las etiquetas automáticas de Recognize). Devuelve solo metadatos, ordenados por `mtime` descendente.

Los argumentos no válidos, una herramienta inexistente o una herramienta sin permiso devuelven el error JSON-RPC `-32602`, sin indicar cuál es el motivo. Los errores de ejecución devuelven `isError: true` con un mensaje genérico, sin ruta física, contenido ni traza de pila.

Consulta la guía `mcp_guide` activa para obtener el esquema y las operaciones disponibles como referencia definitiva.
